S2A PILOT 1.11.3 BÊTA / BRIDGE 1.6.30 BÊTA — MISE À JOUR

1. Sauvegardez les fichiers actuellement déployés et conservez les anciennes archives.
2. Décompressez S2A-Pilot-1.11.3-beta.zip et envoyez son contenu dans le dossier actuel de Pilot, en remplaçant les fichiers de même nom. Ne supprimez pas le dossier distant.
3. Conservez impérativement copilot/config.php et le stockage privé du relais. Cette livraison ne contient ni votre configuration privée ni les journaux serveur.
4. Le relais copilot/ et Bridge 1.6.30 doivent être mis à jour ensemble pour utiliser la nouvelle télécommande QLab. Les anciennes versions de Bridge restent en lecture seule sur le relais.
5. Après installation, purgez le cache CDN si nécessaire, puis actualisez Pilot hors lecture. La version affichée doit être 1.11.3 bêta. actualiser.html permet de renouveler le cache sans effacer les projets locaux.
6. Installez Bridge 1.6.30 depuis son ZIP ou la copie incluse dans Pilot. Dans Bridge, ouvrez Show, puis Copilot. Le popup présente l'autorisation des télécommandes et le code de quatre chiffres. Modifiez le code puis cliquez sur Appliquer. Pilot n'a pas besoin d'être ouvert.
7. Sur le téléphone, scannez le QR code et choisissez Télécommande. Le code est demandé pour accéder aux commandes QLab : GO, lecture/pause, cue précédente/suivante et sélection d'une cue principale. La sélection seule ne lance pas la cue.
8. Un changement de code retire les anciennes autorisations et annule les commandes en attente. Sélectionnez à nouveau Télécommande sur les appareils concernés et saisissez le nouveau code. Cinq codes incorrects depuis une même adresse réseau entraînent une attente de cinq minutes. Le code n'est jamais dans le QR ni dans la conduite partagée.
9. Copilot affiche un seul halo, en priorité sur la sous-cue. Chaque changement place la cue active à 20 pixels sous la timeline. Le défilement manuel reste libre entre les changements. Bridge actualise aussi la sous-cue depuis l'horloge de lecture.
10. Bridge Show utilise Iceman et affiche la fin estimée de la conduite restante, hors attentes de GO. En pause, l'estimation suppose une reprise immédiate. Une durée inconnue donne « Fin indéterminée » ; l'estimation disparaît en cas de perte de synchronisation.

Les migrations du relais sont additives : invitations, membres et Tops Backstage sont conservés. Les anciennes sessions ne reçoivent pas de contrôle à distance sans activation et code.
La branche GitHub bêta reste distincte de main. Cette livraison n'est pas déployée automatiquement sur le site.
